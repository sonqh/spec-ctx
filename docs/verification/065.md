# Verification of change 065-scan-glob

Layer 1, retrieval. It fixes GitHub issue #29. The rule is REQ-IDX-015.

## Reproduction

The setup is the same before and after.

- `spec-ctx.toml` holds `[scan]` and `changes = ["work/changes/**/*.md"]`.
- `work/changes/a/tasks.md` and `work/changes/b/tasks.md` each hold the task `1.1`.
- `specctx build` runs in that folder.

Before, on 0.6.0. The lead ran it on 2026-11-07. Both index entries had the ID `main/1.1`.

After, with the build of this change. I ran it in a temp dir.

```
indexed 4 entries, 0 problem(s) -> .ctx/index.json
"id": "a/1.1"
"id": "b/1.1"
```

The index also holds `change/a` and `change/b`.

## Tests

- `tests/index/scan-glob.test.ts` covers SCN-IDX-015-1 to SCN-IDX-015-4 and four more cases. They are the first-glob rule with a `**/*.md` glob first, a change named like its capability, the default glob, and `activeChanges` for a custom glob.
- `tests/query/file-mentions.test.ts` has a case where `related <file>` finds the active task under `work/changes/**` and not the archived one.
- `tests/query/structural.test.ts` has a case where `related change/a` lists its delta and capability edges under the custom glob.
- `bash tests/parity/run.sh` printed `parity: 7 commands identical`, with no `--record`. No golden changed.

## Edges

- The query commands read the rules from the config and pass them to `structure`, `walkFound`, `related`, `mainVersion`, and `bundle`. A caller that omits them gets the default rules.
- `check`, `next`, `status`, `adopt`, `gate`, and `gate --rerun` read `openspec/changes` by path. On a repo with a custom glob, `activeFolders` in `next` returns no folder, so `next` stops with a clear reason. Another issue holds this.
- `activeChanges` now lists the changes of a custom glob. Their tasks left the change `main`.

## Existing bug left out of scope

- A main spec `openspec/specs/archive/spec.md` still reads as archived. The path test `includes("/archive/")` in `src/index/scan.ts` decides its status, because no changes glob matched it.

## Deviations

- The default glob gave the change `archive` to `openspec/changes/archive/tasks.md`, because the old pattern backtracked. The new rule gives `main`. A test names the case. No golden holds it.
- `scanMarkdown` takes the archive status from the module when a glob yielded a folder. A cap folder named `archive` under a change is now active, not archived. This is the correct result, and a test pins it.
- `src/cli/status.ts` strips the date of the last archived folder with the same expression as `src/check/check.ts`. It no longer calls `changeOf`.
- The before run is the report of the lead. I did not install 0.6.0.
