# Verification of change 067-archive-hygiene

Date: 2026-11-07. Branch `fix/067-archive-hygiene`, stacked on 066. ADR-010 item 3.4. Layer 2, loop hygiene, a bug fix.

## Bug 1, the TBD Purpose

Before. A scratch repo with OpenSpec 1.x, a delta for the new capability `newcap`, no `## Purpose` in the delta. After `openspec archive demo -y` the main spec read:

```
## Purpose
TBD - created by archiving change demo. Update Purpose after archive.
```

`openspec validate --all --strict` then printed `✗ spec/newcap` and a warning that the Purpose is a placeholder. The agent fixed it by hand after the archive.

After. `check --strict` prints `delta-without-purpose  newcap` for that delta. `next` returns `gate` with `check --strict` and a reason that names the delta file and `## Purpose`. With one sentence under `## Purpose` in the delta, the same scratch run archives and the main spec holds the sentence. `validate --all --strict` passes. Tests: `tests/check/purpose.test.ts`, `tests/loop/purpose-stop.test.ts`.

A `TBD` or `TODO` Purpose in a main spec is a warning in both modes of `check`, and it keeps exit 0. `validate --strict` in the gate already fails it.

## Bug 2, the rewritten metrics file

Before. `stats --write` rebuilt the file of the day. The context ratio of each old row divides by the current spec size, so old rows moved. The gate rows come from `.ctx/gate-log.jsonl`, which git ignores. In changes 064 to 066 the file had 49 gate runs and a local log of 28 lines gave 28 runs. The lead restored the file from HEAD each time. The README total row was a hand edit.

After. A write on a day that has a file keeps each change row as written. It adds rows for changes the file lacks. New rows and the total use the spec text size of the file. The three gate rows change together, and only when the log holds at least as many runs as the file. A new day writes a new file. The write also sets the path and the total row under `## Measured` in `README.md`. It does so only when three anchors exist. They are `## Measured`, a line that starts `The newest file is`, and a `| total |` row. Tests: `tests/stats/append.test.ts`. The tests of `tests/stats/cli.test.ts` and `tests/gov/readme.test.ts` stay unchanged and pass.

The end to end run at the archive stop is in the report of the change. It ran the archive guidance as it reads after task 4.1 and left the old rows of `docs/metrics/2026-11-07.md` as they were.

## Golden record

The fixture `tests/fixtures/parity-repo` holds a new capability delta `plant` with no Purpose. `check --strict` now reports `delta-without-purpose plant` there. `bash tests/parity/run.sh --record` changed only `tests/fixtures/parity-golden/check-strict.out`, by 3 added lines and 1 changed line. The exit code stays 1. The other six commands are identical.

The fixture `tests/fixtures/ctx-repo` held a delta `beta` with no Purpose. It gained a `## Purpose` section, so its strict checks stay clean.

## Deviations

- The README line under `## Measured` did not start with `The newest file is`. The first end to end run left the README total row alone. The README now splits that sentence into two paragraphs, so the anchor matches.
- The first build of `stats --write --change X` wrote only the rows of X. It dropped the old rows of the file and wrote the total of X into the README. The fix has three parts. The write takes the rows and the total of the whole repository and merges them with the rows of the file. It does not touch the README under `--change`. A test in `tests/stats/append.test.ts` checks that a write for one change keeps the other row byte for byte and leaves the README as it was.
- The first build of `next` ignored the baseline for `delta-without-purpose`. A baselined finding passed `check --strict` and still blocked `next`. `next` now filters it through the baseline like the citation step does. A test in `tests/loop/purpose-stop.test.ts` covers it.
- The write prints one note on stderr when `README.md` has `## Measured` and lacks the path line or the total row. The note names the missing anchor.
