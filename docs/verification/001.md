## Parity

The harness compares stdout, stderr, the exit code, and `.ctx/index.json` for seven commands. The first full run was identical. Before that run, the Python oracle differed from the spec in the points below. For each point the spec decided the behavior, and the fix went into both engines.

- Index format. The oracle wrote one-space indent and a `scanned` record with `files` and `mtime_ns`. REQ-IDX-002 asks for two-space indent and `count` with `newest_mtime_ms`.
- Scan paths. The oracle walked fixed folders, kept six file extensions, and skipped `tests/fixtures` by name. REQ-IDX-001 and REQ-DIST-002 ask for the globs and `ignore` list of `spec-ctx.toml`. Both engines now use the same glob rules.
- Text field. The oracle filled `text` for ADR and task entries. REQ-IDX-002 says `text` is empty for every kind except req, scn, and decision. A task title still holds the full task line, so query still finds it.
- Decision IDs. The oracle named decisions by the full change folder, for example `001-engine-port/D1`. ADR-002 names them by the change number, for example `002/D3`, as it names tasks.
- Line numbers. The oracle split lines on form feed, U+2028, and other separators, and it read a lone CR as a line break. Editors count LF only. Both engines now split on LF and remove a trailing CR.
- Regex scope. Python patterns matched non-ASCII digits and word characters. Both engines now use ASCII patterns.
- JSON key order. `query --json` and `related --json` printed keys in a different order after a rebuild. Both engines now sort keys.
- New rules from the spec. Both engines report `unknown-cap` from the configured capability codes and accept `check --json`.
