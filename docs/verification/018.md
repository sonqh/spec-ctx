# Verification of change 018-gate-openspec

## Tasks

- 018/1.1 `Config.gate.openspec` in `src/config.ts` holds the command that runs OpenSpec. The default is `npx -y @fission-ai/openspec@latest`. `loadConfig` rejects a value that is not a string or is empty with `gate.openspec must be a string that is not empty`. `INIT_TEXT` has the key under `[gate]` with a two line comment. `tests/config.test.ts` covers SCN-DIST-002-9 and the key count of SCN-DIST-002-2 is 13. Both failed before the fix.
- 018/1.2 `runGate` takes `GateOpts.openspec`. `src/cli/commands.ts` passes `process.env.SPECCTX_OPENSPEC ?? cfg.gate.openspec`, so the env var wins. `gate.ts` reads no env var itself. `tests/cli/gate.test.ts` covers SCN-CLI-004-6 with a shell stand-in that records its arguments, then `/bin/false` from the file and `/bin/true` from the env var. The test failed before the fix. `tests/paths/fresh.sh` and `existing.sh` set no env var and run the default command. Both stayed green with no edit.
- 018/2.1 `TEMPLATES_NOTE` in `src/init/init.ts` joins `InitResult.notes` when the schema step ran, on a write run and on `nothing to do`. `init` prints it after the other notes and before `next:`. The JSON output carries it under `notes`. `tests/init/init.test.ts` covers SCN-SCH-003-5. `tests/cli/nextstep.test.ts` expects the line on the second `init --all`. The test failed before the fix. The printed line passes `lint ste --baseline 0`.
- 018/3.1 README fresh block shows `openspec init --tools <tool>` and one line names `--no-animation`. The existing path list names `[gate] openspec`. The config reference block gets `[gate]` with both keys. The env var row says that it overrides the key. `CHANGELOG.md` gets an `## Unreleased` section. `bun run ci:local` passed.
- After 2.1, `check --strict` reported stale evidence on 1.1 and 1.2, because `src/init/init.ts` and `tests/init/init.test.ts` changed. I reopened and closed both again.
