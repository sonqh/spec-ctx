## Decision order as implemented

The draft put the open question first and the missing change second. The code picks the change first, because the question match needs the change key. The order: no change, open question, OpenSpec status, citation gap, hand tick without evidence, current task, open task, gate, archive. The current task step gives ask at the cap, else fix, else work. A `stop` guard follows that no path reaches. Every `plan` carries `human: true`, because the plan is one of the two human stops of ADR-006 item 4. The object always has the same nine keys, with `null` for a key without a value, so a skill can read any state the same way.
