## Decisions taken inside the spec

- `id new ADR` takes no capability code. `id new DEC <change>` prints `<change number>/D<n>`, the next decision number in that change.
- The evidence path uses the change number, for example `.ctx/evidence/002/3.1.json`. This matches SCN-CHK-003-1 and the task ID.
- `stderr_tail` is one string with at most 20 lines.
- `task done --manual` on a task that a person ticked before this change writes the evidence and keeps the checkbox. The backfill of 6.1 uses that path. On an open task, `--manual` writes manual evidence without a run.
- The handoff stores `base` and `as_of`. `done` lists the evidence after `base`. A write with no new evidence keeps `base`, so two runs give the same bytes.
- `status` prints `open_questions: N` whenever the handoff exists. It lists the questions only when no change is active, as in 001.
- `spec-ctx.toml` gained `[verify] timeout_s` with the default 600.
- `task done`, `task reopen`, and `id retire` delete `.ctx/index.json` after they write. The next command rebuilds the index even when the write lands in the same millisecond as the last build.
- The Python oracle got the three evidence rules and the new `status` lines. The parity fixture holds one stale evidence file and one evidence file for an open task.
