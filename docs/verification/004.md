## Decisions inside the spec

- `adopt --dry-run` exits 1 when headers need an ID and 0 with `nothing to adopt`, like `check` for findings.
- On a CAP collision the shorter path keeps the base code. `user-auth` keeps `UA` and `upload-api` takes `UPA`.
- The baseline file is a sorted JSON list of `"rule id"` strings. A `manual-evidence` warning in the baseline leaves the output too and counts in `baselined: <n>`.
- `adopt` writes every capability code of the plan into `spec-ctx.toml`, the derived ones and the ones already in use. Else the first entry in `[ids] caps` would turn on `unknown-cap` for the codes already in use.
