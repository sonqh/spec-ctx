# Tasks

Run `bun run build` before every Verify. Tests write only under a temp dir. They clear `SPECCTX_RERUN` before they run the CLI or a script. They never reach the network. They set `SPECCTX_OPENSPEC` to `/bin/true` or to `tests/fixtures/openspec-stub.sh`. A test line that holds a tag uses `TAG` or `COVERS` from `tests/helpers.ts`. Then the index of this repository does not read test data as a tag. A task that edits a `.ts` file also runs `bun run typecheck`. `CHANGELOG.md`, `README.md`, and `docs/verification/046.md` change only in task 3.2. Some tests read one parity golden each: `tests/index/determinism.test.ts` reads `index.json` and `tests/query/bundle.test.ts` reads `bundle.out`. So a task re-records the goldens with `bash tests/parity/run.sh --record` when such a test fails on a golden, and it lists the files that differ. The Verify of task 3.2 is the only one that runs the whole parity check. No test reads or writes the real `.ctx/index.json`, because `loadIndex` can rewrite it.
